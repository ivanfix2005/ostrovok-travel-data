# Проверка требований ТЗ

Состояние проверок и реальные ответы на отсутствие доступа записаны в `reports/verification.json` и `reports/live-check.json`. Успешные автоматические тесты проверяют поведение на фиксированных и моделируемых ответах; они не заменяют проверку ключей поставщиков.

24.10.2026 реальные запросы к Яндекс Расписаниям, Яндекс Погоде и 2ГИС завершились успешно. Для отелей подключён парсер публичных гостевых страниц Bnovo без партнёрского ключа; проверены настоящие тарифы на точные даты и состав гостей (`is_fixture=false`). Каталог ограничен тремя объектами в Сочи. Общая приёмка не завершена: отсутствует оригинальный архив контрактов, а точные условия части тарифов требуют подтверждения.

## Что остаётся для завершения приёмки

1. Согласовать язык подключения с backend. Поставка — Python-библиотека; HTTP-сервер не создавался по границе задачи.
2. Получить оригинальный архив схем и сравнить с экспортом. Сейчас неоднозначности nullability и перечислений явно закреплены в восстановленных схемах, но это не подтверждает их совпадение с оригиналом.
3. Настроить три ключа: Яндекс Расписания, REST API Яндекс Погоды, 2ГИС Routing API. Для выбранного Bnovo ключ не нужен; при переключении на Островок отдельно получить партнёрские KEY_ID + API_KEY.
4. Локально заполнить .env, импортировать справочник станций, выполнить live-check. Ключи в чат не отправлять.
5. Согласовать ограничение каталога Bnovo тремя объектами Сочи; при необходимости расширить его подтверждёнными публичными формами других отелей. Синтетические примеры не считать реальной интеграцией.
6. Backend должен показывать необходимые атрибуции, перепроверять цену перед бронированием и обеспечивать общий лимитер, если запускает несколько процессов.
