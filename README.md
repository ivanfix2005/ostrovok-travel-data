# Модуль данных для трека О!дин запрос

Модуль предоставляет четыре функции из ТЗ версии 1.0.0: `search_hotels`, `search_transport`, `get_weather`, `get_route`. Его можно вызвать напрямую из Python или через командную строку без AI-агента. Основной сервер, интерфейс и бронирование в модуль не входят.

**Статус поставки:** реализация, контракты и автономные тесты подготовлены. Живые подключения не подтверждены: у команды пока нет API-ключей. Без ключа возвращается `ACCESS_NOT_CONFIGURED`, а не вымышленная выдача. Все вымышленные примеры включаются только явно через `mode="fixture"`.

**Контракты требуют сверки:** в присланном Word-файле указан отдельный архив полных JSON Schema, примеров и `tools.json`. Архива нет среди переданных материалов. Файлы в `schemas/`, `examples/` и `tools.json` восстановлены по содержимому DOCX. Нельзя утверждать их побайтовую или полную семантическую совместимость с отсутствующим архивом. До подключения команды передайте эти файлы AI- и backend-разработчикам и согласуйте их; при получении оригинала сравните поля, nullability, ограничения строк и перечисления.

## Быстрый запуск в Windows

Если вы получили проект с GitHub или в архиве:

1. Сохраните всю папку проекта на компьютер. Для GitHub нажмите Code → Download ZIP и распакуйте архив либо выполните `git clone`.
2. Установите Python 3.11 или новее, если его ещё нет.
3. Дважды щёлкните `INSTALL.cmd` и дождитесь завершения установки. На этом компьютере окружение уже готово, этот шаг можно пропустить.
4. Дважды щёлкните `START.cmd`. В меню доступны демо, проверка настроек, редактирование ключей и тесты.
5. Чтобы читать и менять код в VS Code, откройте `OPEN_CODE.cmd`.

Текущий результат — модуль данных с запуском в терминале. Демо выводит JSON четырёх функций. Примеры и документация лежат рядом с кодом в `examples/`, `schemas/`, `README.md`. Для реальных запросов заполните локальный `.env`; этот файл не публикуется в GitHub.

Требуется Python 3.11 или новее. В этом рабочем каталоге создано окружение `.venv` на установленном Python 3.15.1. Git и VS Code уже доступны. База, Docker, Node.js и локальная нейросеть для этого модуля не нужны.

В PowerShell из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m travel_data demo
.\.venv\Scripts\python.exe -m travel_data doctor
.\.venv\Scripts\python.exe -m pytest -q
```

`demo` показывает четыре **вымышленных** ответа. `doctor` проверяет настройки без раскрытия ключей. Демо фиксировано на 23 октября 2026 года и проверяет только запросы из `examples/`; оно не сочиняет цены на произвольные даты. Изменённый запрос может вернуть пустую выдачу или `OUT_OF_COVERAGE`.

Для установки на другом компьютере выполните `scripts/setup.ps1`. Скрипт создаёт `.venv`, устанавливает зафиксированные зависимости и пакет. Исходники остаются редактируемыми.

## Что передать коллегам в начале

- `schemas/*.request.schema.json`: четыре полные схемы обёртки вызова.
- `schemas/*.response.schema.json`: четыре схемы ответов.
- `examples/*.request.json` и `examples/*.response.json`: четыре успешных примера, пустой результат и ошибка.
- `tools.json`: нейтральные определения четырёх инструментов; `input_schema` описывает только `arguments`.
- `README.txt`: краткие единицы и правила интеграции.

Backend создаёт `request_id` и `schema_version`; модель передаёт только `arguments`. Вход не принимает URL, API-ключи, названия поставщиков или HTML-селекторы. Неизвестные поля запрещены.

## Прямой вызов из Python

```python
from travel_data import search_hotels

response = search_hotels(
    {
        "location": {"city": "Сочи", "country_code": "RU"},
        "check_in": "2026-11-10",
        "check_out": "2026-11-17",
        "guests": {"adults": 2, "children_ages": [7]},
        "max_total_price_minor": 8_000_000,
        "meal": "BB",
        "pets_required": True,
        "free_cancellation_required": True,
        "limit": 3,
    },
    request_id="backend_001",
    mode="fixture",  # убрать для обращения к реальному источнику
)
```

Имена и типы одинаковы в fixture и live. Синхронные `search_transport`, `get_weather`, `get_route` вызываются так же. В live прошлые даты отклоняются, поэтому для реальных запросов задавайте будущие даты.

Для асинхронного backend используйте один клиент на жизненный цикл приложения:

```python
from travel_data import TravelDataClient


async def get_data(request):
    async with TravelDataClient() as client:
        return await client.execute(request)
```

В длительно работающем backend храните открытый клиент в lifespan приложения. У клиента также есть четыре асинхронных метода. Синхронные обёртки внутри работающего asyncio loop не используются. Ошибка неизвестного имени инструмента поднимает `DataError`, поскольку для него нет согласованной схемы ответа. Ошибки аргументов известных инструментов возвращаются в JSON.

Вызов из файла:

```powershell
.\.venv\Scripts\python.exe -m travel_data call examples/get_weather.request.json --mode fixture
```

## Доступы к реальным источникам

Скопируйте `.env.example` в `.env` и заполните значения локально. Не отправляйте ключи в чат, не добавляйте `.env` в Git и не включайте его в архив. Также можно передать переменные через окружение процесса. Окружение имеет приоритет над `.env`.

### Отели через Островок API

Нужны `OSTROVOK_KEY_ID` и `OSTROVOK_API_KEY`. Получение ключей: https://help.b2b.ostrovok.ru/ru/articles/9330513 . Это партнёрский доступ; наличие документации не означает, что ключ выдадут немедленно. Организаторы хакатона ключей не обещают. Sandbox и production имеют разные возможности; тестовый отель не подтверждает наличие реальных предложений.

Адаптер использует автодополнение регионов, SERP-поиск по региону и контент отелей. Город выбирается только при точном единственном совпадении названия, страны и типа City. Для одного номера источник ограничивает состав шестью взрослыми и четырьмя детьми, период — 30 ночами; более широкий валидный по общему контракту запрос получает `UNSUPPORTED_REQUEST`.

Цена берётся из `show_amount` в RUB для точных дат и группы, не из `daily_prices`. Полнота обязательных сборов консервативно остаётся `null`; при явных невключённых налогах — `false`. Животные — `null`: свободный текст и общий amenity-флаг не подтверждают приём конкретного питомца. `nomeal` не превращается в RO. Бесплатная отмена преобразуется из документированного UTC в ISO 8601 с зоной. Тарифы только для пакета исключаются. Поисковую цену необходимо перепроверить перед бронированием — оно относится к backend.

Ограничение кандидатов: одна страница до 10 отелей и до 100 тарифов каждого; возвращается до пяти подходящих предложений. При оставшихся кандидатах `has_more=true`. Не обещается поиск всех отелей страны или всех страниц. Получение недостающего контента входит в общий бюджет 15 секунд; официальный лимит метода hotel/info 30 запросов в минуту соблюдается в процессе. Для рабочего развёртывания с несколькими процессами backend должен обеспечить общий лимитер по ключу.

Можно отдельно импортировать разрешённую выгрузку контента в формате JSONL либо JSONL.GZ: `python -m travel_data import-hotels путь_к_файлу`. Если поставщик выдал Zstandard-архив, сначала распакуйте его штатным инструментом поставщика. Импорт сохраняет только названия, адреса и координаты, а не фотографии, отзывы и полный контент.

Документация: https://docs-api.ostrovok.ru/docs/b2b-api/hotel-search/search-by-region/ , https://docs-api.ostrovok.ru/docs/b2b-api/hotel-search/suggest-hotel-and-region/ , https://docs-api.ostrovok.ru/docs/b2b-api/static-content/retrieve-hotel-content/ .

### Транспорт через Яндекс Расписания

Нужен `YANDEX_RASP_API_KEY`, который создаётся в кабинете разработчика Яндекса. Документация: https://yandex.ru/dev/rasp/doc/ru/ .

Перед первым поиском отдельно загрузите справочник городов:

```powershell
.\.venv\Scripts\python.exe -m travel_data import-stations
```

Большая выгрузка не скачивается внутри функции поиска. По умолчанию импортируются населённые пункты России; другую страну можно выбрать через `--country-name` и `--country-code`. Совпадающие названия сохраняются, а не сливаются: если код города неоднозначен, возвращается `AMBIGUOUS_LOCATION`. Неизвестное название также требует уточнения или расширения справочника.

Поддержаны plane, train, bus. Возвращаются расписания в одну сторону, до 100 исходных кандидатов за один запрос. Цены из `tickets_info` сохраняются только как `advertised_price` с `basis="unknown"`. Они не умножаются на гостей и не выдаются за итог группы. `total_price=null`, `match_status=requires_confirmation`. Пересадки разбираются, если все транспортные сегменты соответствуют запрошенному виду; интервальные рейсы без точного отправления исключаются с предупреждением. Неизвестное время не получает вымышленную зону. Backend должен показывать атрибуцию «Яндекс Расписания» по условиям источника.

Метод: https://yandex.ru/dev/rasp/doc/ru/reference/schedule-point-point . Импорт: https://yandex.ru/dev/rasp/doc/ru/reference/stations-list .

### Погода через Яндекс Погоду

Нужен `YANDEX_WEATHER_API_KEY` с доступом к REST v2 forecast. Данные и горизонт зависят от тарифа; ключ другого API или тарифа может не подойти. Документация: https://yandex.ru/dev/weather/doc/ru/concepts/forecast-rest .

Возвращаются только доступные дни в интервале `[start_date, end_date)`, максимум 16 дней по контракту. Реальный источник может дать меньше. Пробелы приводят к `partial` с перечислением дат; отсутствие покрытия — к `OUT_OF_COVERAGE`. `prec_prob` делится на 100. Осадки в миллиметрах не заменяют вероятность, температура воздуха не заменяет температуру воды. `now_dt` не выдаётся за время обновления модели прогноза.

### Маршруты через 2ГИС

Нужен `DGIS_API_KEY` с доступом к Routing API. Демо-ключ создаётся в менеджере платформы; по документации демо ограничено маршрутами до 50 км. Документация и регистрация: https://docs.2gis.com/api/navigation/routing/start .

Используется автомобильный дорожный маршрут. Из ответа берутся total_distance и total_duration, возвращается один вариант. Геометрия и навигационные инструкции удаляются. Запрос использует текущие пробки, но без подтверждения сервером типа использованных данных `traffic_mode` остаётся `unknown` с предупреждением. Явно заданное `departure_at` этот адаптер не поддерживает: возвращает `UNSUPPORTED_REQUEST`.

## Контракт и ограничения

- Деньги — целое число копеек, только RUB. 8 000 000 = 80 000 рублей. Бюджет относится только к проживанию.
- Цена за ночь или одного взрослого не выдаётся за итог группы. advertised_price не прибавляется к total_price.
- Один номер на группу, один вызов транспорта на одну сторону, один автомобильный маршрут.
- Даты — YYYY-MM-DD; время — ISO 8601 с UTC offset. Проверка прошедшей даты использует UTC дату часов приложения; fixture использует фиксированные часы.
- Статусы: ok, empty, partial, error. При error items пуст и заполнен error; при остальных error=null.
- У каждой записи есть источник через meta.source_name; время получения и известное время обновления различаются.
- Неизвестное обязательное условие даёт unknown и requires_confirmation. Известное нарушение обязательного фильтра исключает предложение.
- Сортировка проживания: полная известная цена, неполная известная цена, неизвестная цена; внутри группы цена по возрастанию и id.
- Общий бюджет на функцию не более 15 секунд, включая очередь, повторы и дополнительные обращения. Не более одного повтора временного сбоя на всю функцию. 401/403 и 429 не повторяются.
- В одном процессе не более двух одновременных обращений к одному хосту даже из нескольких клиентов. При нескольких процессах/серверах общий лимитер обеспечивает инфраструктура backend. Соблюдайте меньшие квоты из договора; 429 возвращается явно.
- Ответ ограничен 32 000 байт UTF-8; при необходимости уменьшается items с has_more=true и предупреждением, JSON никогда не обрезается посередине.
- Кеш по умолчанию выключен. Включайте CACHE_ALLOWED и TTL только при разрешении поставщика. Ключ содержит инструмент и все arguments. Ошибки и partial не кешируются. Просроченный кеш не выдаётся. Повторное чтение помечено cache_hit; fetched_at сохраняется от исходной загрузки.
- Модуль не исполняет HTML, скрипты или инструкции из данных. Запросы выполняет код. Секреты исключены из JSON, исключений и стандартных URL-логов HTTPX.

## Проверки и дальнейшая приёмка

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe scripts/build_contracts.py --check
.\.venv\Scripts\python.exe -m travel_data live-check --output reports/live-check.json
```

`live-check` создаёт даты относительно реального дня запуска. При отсутствии ключей сохраняет ошибки и завершает процесс с кодом 2. Успешный offline-тест или fixture не отмечается как реальная проверка. Для приёмки нужны успешные реальные запросы по включённым источникам и сравнение с оригинальным архивом контрактов. Вспомогательный doctor никогда не утверждает live_verified без сетевой проверки.

`python scripts/package_handoff.py` собирает архив команды в `dist/`; `.env`, `.venv` и импортированные данные в него не попадают.
